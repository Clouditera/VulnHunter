强化点： ①pill 带隐约阴影 + hover 上浮反馈； ②展开浮层是独立 popover（不影响页面布局）； ③meta 条显示当前 stage + 进度条 + 实时耗时，直观判断任务健康； ④底部"在新页面打开完整日志"作为深度查看入口； ⑤完成 / 失败态 pill 自动变色，5 秒后淡出消失（可配置）。

A vs B 对比 同一套 visual system，选择基于布局哲学

A · Inline 折叠卡片

  • ✅ 日志是任务详情的一部分，视觉上统一
  • ✅ 查看日志不打断浏览流
  • ✅ 折叠态占用 50px 高度（几乎无感）
  • ⚠️ 展开时会把下方内容推下去
  • ⚠️ 切换到漏洞/报告 Tab 时日志不可见

B · 浮动 Pill + Popover

  • ✅ 详情页完全不被日志占用
  • ✅ 切 Tab 时 pill 常驻可见，一眼可查看状态
  • ✅ 浮层打开在右下，符合 VSCode Notification 直觉
  • ⚠️ 日志不是"主内容"，容易被忽视
  • ⚠️ 需处理多任务场景（一个 pill 还是多 pill）

请最终选择 A / B / 混合

  • 选 A：inline 折叠卡片 + 浅色统一（当前已很接近，需加深色→浅色 + filter + 自动滚动）
  • 选 B：浮动 pill + 弹出 popover（改动较大，需新建 floating root 组件）
  • 混合：比如"多数情况 A inline，切到 Findings/Reports Tab 时退化成 B pill"—— 让日志永远可见但不越权占用空间
