# CVSS v3.1 评分参考

评估漏洞严重性时使用此参考。CVSS 向量由 8 个基础指标组成，必须逐项推导，不得套用模板。

## 向量格式

```
CVSS:3.1/AV:_/AC:_/PR:_/UI:_/S:_/C:_/I:_/A:_
```

## 评估要求

**每个 finding 的 CVSS 评估必须逐项列出 8 个指标的取值和判断理由。** 禁止跳过推导直接给出向量。

## 基础指标

### Attack Vector (AV) — 攻击向量

评估攻击者需要多"近"才能利用漏洞。

| 值 | 含义 | 判断标准 |
|---|---|---|
| **N** (Network) | 远程网络 | 漏洞可通过网络协议栈利用，不需要物理或本地访问 |
| **A** (Adjacent) | 相邻网络 | 攻击限于同一物理或逻辑网络段 |
| **L** (Local) | 本地 | 攻击者需要本地访问（登录系统、打开恶意文件） |
| **P** (Physical) | 物理 | 需要物理接触设备 |

判断要点：
- 客户端软件连接恶意服务端（如 FFmpeg 播放恶意 RTSP 流）→ **AV:N**
- 用户主动打开攻击者提供的本地文件 → **AV:L**
- 网络协议自动获取并处理的数据（如 HLS 分片、HTTP 响应体）→ **AV:N**
- 需要控制 filtergraph 参数或 API 调用方式 → 通常 **AV:L**

### Attack Complexity (AC) — 攻击复杂度

评估攻击者**无法控制**的条件是否影响利用成功率。AC 只考虑攻击者无法控制的因素。

| 值 | 含义 | 判断标准 |
|---|---|---|
| **L** (Low) | 低 | 攻击可重复、可靠利用，不依赖攻击者无法控制的条件 |
| **H** (High) | 高 | 利用依赖攻击者无法控制的条件 |

AC:H 的典型场景：
- 需要赢得竞态条件
- 需要 MITM 位置
- 需要特定内存布局或堆状态
- 需要非默认的可选编译依赖（如 `--enable-libzmq`、`--enable-libtensorflow`）
- 需要目标使用罕见配置或非典型 API 调用方式

AC:L 的典型场景：
- 攻击者完全控制恶意输入内容
- 默认构建配置即可触发
- 常见使用场景下可重复利用

### Privileges Required (PR) — 所需权限

评估攻击者在**目标系统**上需要的权限级别。攻击者在自己控制的系统上的权限不算。

| 值 | 含义 |
|---|---|
| **N** (None) | 不需要在目标系统上有任何权限或账户 |
| **L** (Low) | 需要普通用户权限 |
| **H** (High) | 需要管理员权限 |

### User Interaction (UI) — 用户交互

评估除攻击者之外的用户是否需要参与。

| 值 | 含义 |
|---|---|
| **N** (None) | 漏洞可以在无用户交互的情况下被利用 |
| **R** (Required) | 需要用户执行某个动作 |

判断要点：
- 服务端处理网络请求 → **UI:N**
- 客户端自动处理服务端响应（用户不知道响应是恶意的）→ **UI:N**
- 用户需要主动打开恶意文件、点击链接、连接特定服务 → **UI:R**

### Scope (S) — 影响范围

| 值 | 含义 |
|---|---|
| **U** (Unchanged) | 影响范围限于漏洞所在组件的安全域 |
| **C** (Changed) | 影响超出漏洞组件，波及其他组件的安全域 |

大多数库漏洞（如 FFmpeg、libcurl）是 **S:U**。S:C 仅用于沙箱逃逸、虚拟机逃逸、XSS 等跨安全域场景。

### Confidentiality / Integrity / Availability (C/I/A) — 影响三元组

**C/I/A 必须基于已证明或高度确信的影响，不得基于理论推测。**

| 值 | C (机密性) | I (完整性) | A (可用性) |
|---|---|---|---|
| **H** | 可获取关键敏感数据 | 可执行任意代码或修改任意数据 | 可完全中断服务 |
| **L** | 可获取部分非关键信息 | 可修改部分数据，范围有限 | 可降低性能或部分中断 |
| **N** | 无影响 | 无影响 | 无影响 |

**C/I/A 判断规则**：

1. **越界读（OOB read）**：已证明可泄露敏感数据 → C:H；只能读到相邻无意义内存 → C:L；仅导致崩溃 → C:N
2. **越界写（OOB write）**：已证明可控写入内容和位置 → I:H；写入内容或位置不可控（如固定 NUL 写）→ I:L；仅导致崩溃 → I:N
3. **空指针解引用（null deref）**：通常只是 → C:N/I:N/A:H
4. **UAF / 堆破坏**：如果释放后对象可被攻击者控制的数据占位 → C:H/I:H/A:H；如果只是崩溃 → C:N/I:N/A:H
5. **整数溢出**：如果导致后续可控缓冲区溢出 → 按溢出的实际影响评；如果只导致逻辑错误或 DoS → C:N/I:N/A:H 或更低
6. **SSRF / 信息泄露**：按实际泄露的内容和可达性评估，不要默认 C:H

**禁止**：
- 仅凭"内存安全漏洞理论上可达到代码执行"就标 C:H/I:H/A:H
- 对只证明了 DoS 的漏洞标 I:H 或 C:H
- 对越界读标 I:H

## 分数映射

| CVSS 分数 | severity |
|---|---|
| 9.0 – 10.0 | critical |
| 7.0 – 8.9 | high |
| 4.0 – 6.9 | medium |
| 0.1 – 3.9 | low |
| 0.0 | info |
