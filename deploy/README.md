# VulnHunter Production Install

## Quick start

```bash
sha256sum -c vulnhunter-release-<version>.tar.gz.sha256
tar -xzf vulnhunter-release-<version>.tar.gz
cd vulnhunter-release-<version>
./install.sh
./doctor.sh
```

Open `http://<server>:23000/`, activate license, bootstrap admin, then configure model credentials.

## Important files

- `.env` — deployment config generated from `.env.example`. Existing installs must preserve this file during upgrades.
- `.vulnhunter-install.json` — install manifest written after a successful install/upgrade. It records non-secret install inventory and is used as an upgrade safety marker.
- `$DATA_DIR/.secrets/vulnhunter-master.key` — credential encryption key generated by `install.sh`. Back it up with DATA_DIR. Never regenerate it for an existing deployment.
- `images/*.tar` — offline Docker images loaded by `install.sh` when present.
- `checksums.sha256` — package-internal checksums. `install.sh` verifies it before loading images.

## Commands

- `./install.sh` — clean first install only: preflight, generate config/secrets, load local offline images, start services, write install manifest. If an existing install marker is found, it refuses and tells you to use `./upgrade.sh`.
- `./doctor.sh` — check web, API, service health, Docker socket, worker images, master key.
- `./upgrade.sh` — existing install upgrade only: requires `.env`, backs up config/secrets/manifest, loads local offline images, merges new env keys, syncs release image tags, restarts, runs doctor, updates manifest.
- `./uninstall.sh` — stop services, keep data.
- `./uninstall.sh --purge` — stop services and remove compose volumes.

## Same-directory upgrade

For a server that already has VulnHunter installed in this directory, do not run `install.sh` again. Extract the new release over the existing install directory, preserving `.env` and DATA_DIR, then run:

```bash
./upgrade.sh
```

`upgrade.sh` does not contact Docker Hub: it loads `images/*.tar`, checks every image referenced by compose/worker settings exists locally, and starts compose with pull disabled. If any image is missing, it fails before `compose up`.

## Defaults

- Web URL: `http://<host>:23000/`
- Data dir: root defaults to `/opt/vulnhunter/data`; normal-user interactive installs default to `$HOME/vulnhunter-data`.
  - `install.sh` sets `SERVICE_UID/SERVICE_GID` to the installer user for normal-user installs so the service can read/write the data dir and secrets.
- Master key: `$DATA_DIR/.secrets/vulnhunter-master.key`
- Source archive upload limits use two layers: `UPLOAD_GATEWAY_LIMIT_MB` is the deployment ceiling and drives packaged web nginx plus the maximum value admins can configure; Settings controls the user-facing source archive upload limit and must be `<= UPLOAD_GATEWAY_LIMIT_MB`.
- Enterprise/license information: official customer release packages set `EDITION=enterprise` and include `.secrets/license-public.pem`. For older installs that do not show license information, set `EDITION=enterprise` in `.env`, ensure `LICENSE_PUBLIC_KEY_FILE=./.secrets/license-public.pem` and `VULNHUNTER_LICENSE_PUBLIC_KEY_FILE=/run/secrets/license-public.pem`, then restart `service`/`web` and activate with the customer license.

## Troubleshooting

- Port occupied: change `WEB_PORT` in `.env`.
- Master key path is directory: remove the directory and rerun `install.sh`; it must be a file.
- Service cannot write `.install_id`: run `./doctor.sh` and check `SERVICE_UID/SERVICE_GID`. For normal-user installs they must match `id -u` / `id -g`; for root installs ensure data and `.secrets` are owned by `1001:1001`.
- Docker unavailable: ensure Docker daemon is running and current user can access it.
- Service cannot access Docker socket: rerun `install.sh` so `DOCKER_GID` is detected from `/var/run/docker.sock`, or set `DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)` in `.env` and restart.
- Worker image missing: rerun install with `images/*.tar` present or build/load images manually.
